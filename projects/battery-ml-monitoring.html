In brief

Observability for battery-health models after deployment. Battery ML models can become less reliable after deployment as chemistry, temperature and degradation conditions change.

PythonDrift detectionML monitoringDashONNX
01 / CASE STUDY

Problem & motivation

Battery ML models can become less reliable after deployment as chemistry, temperature and degradation conditions change.

02 / CASE STUDY

My contribution

Built a battery-oriented monitoring workflow with dataset handling, multi-model inference, drift and performance checks, alerting and export hooks.

03 / CASE STUDY

Method and implementation

Dataset registry → preprocessing and model inference → drift / performance monitoring → alerts, reporting and potential retraining workflows.

04 / CASE STUDY

Results and evidence

Repository documents an implemented monitoring stack with battery-focused demos and CLI tools; no independent field-performance metric is claimed here.

05 / CASE STUDY

Limits and future work

Production fleet deployment and independently verified reliability statistics are not established by the available repository documentation. Validate on longer multi-chemistry ageing datasets and connect monitoring outputs to real edge deployments.

RESEARCH DESIGN

Question, model and validation method

Research objective

Develop monitoring tools that can detect when deployed battery-health ML models become unreliable as incoming data changes.

Computational formulation

Battery dataset registry → model inference → drift and performance checks → monitoring reports / alerting / retraining workflows.
